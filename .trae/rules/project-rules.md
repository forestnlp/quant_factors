# 项目规则（quant_factors）

本文件为项目级**硬性工程规则**，当前项目所有目录、所有开发任务统一生效。

> 项目目标 / 技术分工 / 环境见根目录 [PROJECT.md](../../../PROJECT.md)；开发方法论见 [methodology.md](./methodology.md)。

## 1. 代码风格

- **Python**: 遵循 PEP 8，公开 API 使用类型注解与 docstring。
- **命名**: 统一 `snake_case`。
- **注释**: 中文项目使用中文注释。
- **配置**: 环境变量与路径配置集中在 `.env` / 配置文件中，不硬编码。

## 2. 测试与验证期望

- 新功能需有可验证的成功标准（见 methodology.md 第 4 条）。
- 使用 pytest 编写测试；外部服务（网络下载、API）进行 mock 或本地化。

## 3. 数据本地化

- 保持数据本地化，方案服从 `.env` 中 `QLIB_URI` 指向的真实数据情况。
- 配置尽量使用环境变量。

## 4. 目录规划（二区隔离 + 数据区）

项目采用**二区隔离**，避免引擎代码与实验产物污染：

| 目录 | 性质 | 是否入库 | 说明 |
|------|------|---------|------|
| `research/` | **引擎工作区（提炼/验证）** | ✅ 版本控制 | Harness Loop 核心代码，未最终定型 |
| `src/` | **正式区** | ✅ 版本控制 | 经过验证、可复用的正式代码，扁平结构 |
| `data/` | 数据区 | ❌ gitignore | 由 `.env` 的 `QLIB_URI` 指向，不纳入版本控制 |
| `.tools/` | 工具区 | ❌ gitignore | 第三方工具及其专用 venv（如 jqcli），与 conda 环境严格隔离，可随 clone+venv+pip 三步重建 |

**核心原则**：

1. **不污染正式区** — 引擎代码先写 `research/`，运行验证通过后再提升到 `src/`。
2. **单线递进流动** — 代码遵循「`research/`(提炼验证) → `src/`(正式)」的升级路径；`research/` 是提升前的验证层。
3. **提升标准** — 提升到 `src/` 需满足：逻辑正确且通过验证、可复用、有清晰接口与文档、不依赖实验环境。
4. **数据本地化** — 数据保存在本地，不依赖每次联网。
5. **取数完整** — 数据采集须覆盖**日线与分钟线**两种粒度（如 qlib 全市场日线 + 东财标的分钟K），满足因子研究与日内策略两类场景。
6. **验证闭环** — 每个脚本自带可验证的成功标准，跑通后再决定是否提升。
7. **产物不外泄** — 所有日志、结果、缓存只写入项目 `data/` 内，不得写项目目录之外。
8. **项目信息零外泄（硬性）** — 本项目的任何代码、文档、配置、数据、凭据、研究结论，一律不得写入、复制到、下载到项目目录树之外的任何位置；也不得粘贴进外部网页、云端环境、第三方服务或对话之外的渠道。工具、虚拟环境、第三方依赖若需落盘，必须置于项目内（如 `.tools/`）并在 `.gitignore` 中忽略。外部服务（如聚宽、AKShare）仅作为**只读取数通道**：取回的数据沉淀进 `data/`，但绝不把本项目的内容反向传给它们（上传到云端执行的脚本必须只含取数逻辑，不含本项目的因子、结论、凭据）。
9. **数据本地化优先，外部平台只做增强件** — 评估引擎依赖的数据必须驻留本地（`data/cn_data`）；云端平台（聚宽等）只承担"拉取本地无法获得的独有数据"（行业 PIT、财务公告日、涨跌停价），且须低频克制使用，其产物一律本地落盘。任何关键路径不得建立在外部平台可用性之上。
